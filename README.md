# 🛡️ NFT-GW Web Manager

Легковесный сетевой шлюз, веб-интерфейс и автоматический установщик для управления **`nftables`** и **`Fail2ban`** в виртуальной инфраструктуре (Proxmox VE / KVM / LXC / Debian / Ubuntu).

Создан специально для роли пограничного шлюза (VPC / Gateway):
* **Чистый файл конфигурации:** `/etc/nftables.conf` сохраняет человекочитаемый вид, структуру и комментарии, полностью пригоден для прямого редактирования в nano/vim.
* **Сверхлегкий:** бинарник на Go потребляет всего **~10–15 МБ RAM**.
* **Автономный:** компилируется в один статичный бинарник без внешних зависимостей (Node.js, Python, Nginx не требуются).
* **Мобильный интерфейс:** адаптивная верстка с поддержкой смартфонов, планшетов и десктопов.
* **Встроенный Fail2ban:** блокировка брутфорс-атак на уровне ядра через nftables sets.
* **Безопасность:**
  * Порт по умолчанию: **`8443`** (HTTP).
  * Вход **только по паролю администратора** (логин не требуется).
  * Защита от подбора: встроенный Rate Limiter (после 5 неверных попыток IP блокируется на 10 минут).
  * Защита от инъекций: строгая валидация сетевых параметров и синтаксиса `nft -c -f`.
  * Хранение конфигурации в защищенном файле `/etc/nft-web.conf` (права `0600`).
  * Возможность ограничить доступ к вебке по белому списку IP.

## 🚀 Быстрый старт на новом шлюзе (Debian 11/12, Ubuntu 22.04/24.04)

Для установки на свежую ВМ или LXC-контейнер выполните:

```bash
git clone https://github.com/Ttolyanich/nft-web.git /opt/nft-web
cd /opt/nft-web
chmod +x install.sh
sudo ./install.sh
```

При запуске скрипт предложит ввести желаемый пароль администратора (или сгенерирует криптографически стойкий автоматически).

### Что сделает инсталлятор `install.sh`:
1. **Настроит ядро (`sysctl`):** создаст `/etc/sysctl.d/99-gateway.conf` (`net.ipv4.ip_forward = 1`, защита от ICMP redirect и SYN Flood).
2. **Установит зависимости:** `nftables`, `fail2ban`, `curl`, `iproute2`, `golang-go`.
3. **Настроит Fail2ban:** подключит нативный бэкенд `banaction = nftables-multiport`.
4. **Определит сетевые интерфейсы:** автоматически найдет внешний интерфейс (WAN) и внутренний (LAN).
5. **Развернет чистый `/etc/nftables.conf`:** базовые цепочки, защита от поврежденных пакетов (`ct state invalid drop`), маскарадинг (NAT) и белый список `@admin_ips`.
6. **Соберет и запустит службу:** скомпилирует бинарник `/usr/local/bin/nft-web`, сохранит хеш пароля в `/etc/nft-web.conf` и активирует сервис `nft-web.service` на порту **8443**.

## 🖥️ Возможности веб-интерфейса

1. **📊 Обзор & Статус:**
   * Статус nftables, `sysctl net.ipv4.ip_forward` и Fail2ban.
   * Список сетевых интерфейсов, их состояние (UP/DOWN), MAC и IP-адреса.

2. **🛡️ Входящие порты шлюза (INPUT):**
   * **Тумблеры стандартных служб:**
     * 🔑 **SSH (порт 22):** переключение между режимами *«Только @admin_ips»* и *«Разрешен всем»*.
     * 🌐 **HTTP (порт 80):** включение локального веб-сервера. Если порт 80 уже проброшен через DNAT на внутреннюю ВМ, тумблер автоматически блокируется во избежание сетевого конфликта!
     * 🔒 **HTTPS (порт 443):** включение локального HTTPS. Также автоматически блокируется при наличии DNAT проброса.
     * 📡 **ICMP Ping:** включение/выключение ответов на пинги.
     * 🔒 **OpenVPN (1194/UDP)** и ⚡ **WireGuard (51820/UDP):** тумблеры VPN-доступа.
   * **Кастомные порты:** форма открытия любых портов на шлюзе (например, 10050 для Zabbix Agent) с разграничением (*Только @admin_ips*, *Только LAN* или *Всем*).

3. **📝 Белый список (@admin_ips):**
   * Управление доверенными IP-адресами.
   * Изменения применяются **мгновенно на лету** через `nft add/delete element` и синхронизируются в файл на диске без сброса сетевых сессий.

4. **🔀 Проброс портов (DNAT / Port Forwarding):**
   * `Протокол (TCP/UDP) -> Внешний порт -> LAN IP:Порт -> Комментарий`.
   * Автоматически создает правило `dnat to` в `PREROUTING` и разрешающее правило в `FORWARD`.

5. **🚫 Fail2ban (Блокировки):**
   * Список заблокированных адресов в реальном времени.
   * Разблокировка в 1 клик и ручная отправка подозрительных IP в бан.

6. **⚙️ Редактор конфига (`/etc/nftables.conf`):**
   * Встроенный полноэкранный редактор.
   * Кнопка **«Проверить синтаксис»** (`nft -c -f`). При синтаксической ошибке система не применит поврежденный файл и выведет точную строку ошибки.

7. **🌐 NAT Соединения (Conntrack):**
   * Мониторинг активных трансляций и сетевых сессий клиентов шлюза в реальном времени.

## ⚙️ Управление службой и безопасность

Конфигурационный файл хранится в `/etc/nft-web.conf`:
```json
{
  "listen": "0.0.0.0:8443",
  "password_hash": "a665a45920422f9d417e4867efdc4fb8a04a1f3fff1fa07e998e86f7f7a27ae3",
  "allowed_ips": ["203.0.113.10", "10.20.9.0/24"],
  "nft_config": "/etc/nftables.conf"
}
```

* **Смена пароля:**
  Чтобы задать новый пароль вручную, сгенерируйте хеш:
  ```bash
  echo -n "НовыйПароль" | sha256sum
  ```
  и вставьте полученный хеш в поле `"password_hash"`, после чего перезапустите службу:
  ```bash
  systemctl restart nft-web
  ```

* **Ограничение доступа по IP к самой вебке:**
  Укажите доверенные IP/подсети в массиве `"allowed_ips"`. Любые другие IP-адреса получат `403 Forbidden` еще до экрана авторизации.

* **Команды управления:**
  ```bash
  systemctl status nft-web
  systemctl restart nft-web
  journalctl -u nft-web -f
  ```
